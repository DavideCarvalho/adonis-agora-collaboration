import { Callout } from 'fumadocs-ui/components/callout';

1.0 removes a few names and fields that had a replacement already. Each section below is one
change: what to look for in your app, and what to write instead.

<Callout type="info">
  Both packages need Node.js 24 or newer.
</Callout>

## `useComments().create` takes no `authorName`

The comment's author, name included, is the user the request authenticated as. Drop `authorName`
from the call.

Before:

```tsx title="inertia/components/comment_box.tsx"
const { create } = useComments({ docName, space: 'text' })

await create({
  space: 'text',
  anchor: { kind: 'text-range', start: 120, end: 160, selectedText: 'the sentence' },
  body: 'rephrase this',
  authorName: currentUser.name,
})
```

After:

```tsx title="inertia/components/comment_box.tsx"
const { create } = useComments({ docName, space: 'text' })

await create({
  space: 'text',
  anchor: { kind: 'text-range', start: 120, end: 160, selectedText: 'the sentence' },
  body: 'rephrase this',
})
```

The name shown on the comment comes from `resolveUser`. If your comments showed the wrong name,
return the one you want there:

```ts title="config/collaboration.ts"
routes: {
  resolveUser: (ctx) => ({ id: String(ctx.auth.user!.id), name: ctx.auth.user!.fullName }),
}
```

## `createComment(config, input)` takes no `authorName`

Same change for the REST helper.

Before:

```ts
await createComment(config, {
  documentName: 'researches/42/writing',
  space: 'text',
  anchor,
  body: 'rephrase this',
  authorName: currentUser.name,
})
```

After:

```ts
await createComment(config, {
  documentName: 'researches/42/writing',
  space: 'text',
  anchor,
  body: 'rephrase this',
})
```

On the server, `manager.comments.create(docName, { ..., userId, authorName })` is unchanged: a
controller of your own still sets both from the session.

## `signPartyKitToken` and `verifyPartyKitToken` are gone

Every engine signs the same token. Use `signCollabToken` and `verifyCollabToken`, with the edge
key (`partykit.jwtSecret`) when you are talking to the PartyKit worker. They are exported from the
package root; `@adonis-agora/collaboration/drivers/partykit` no longer re-exports them.

Before:

```ts title="app/collaboration/controllers/edge_token_controller.ts"
import type { HttpContext } from '@adonisjs/core/http'
import env from '#start/env'
import { signPartyKitToken } from '@adonis-agora/collaboration/drivers/partykit'

export default class EdgeTokenController {
  async show({ auth, request }: HttpContext) {
    const token = signPartyKitToken(
      { userId: String(auth.user!.id), docName: request.input('doc') },
      env.get('COLLAB_JWT_SECRET'),
    )
    return { token }
  }
}
```

After:

```ts title="app/collaboration/controllers/edge_token_controller.ts"
import type { HttpContext } from '@adonisjs/core/http'
import env from '#start/env'
import { signCollabToken } from '@adonis-agora/collaboration'

export default class EdgeTokenController {
  async show({ auth, request }: HttpContext) {
    const token = signCollabToken(
      { userId: String(auth.user!.id), docName: request.input('doc') },
      env.get('COLLAB_JWT_SECRET'),
    )
    return { token }
  }
}
```

`verifyPartyKitToken(token, secret, docName)` becomes `verifyCollabToken(token, secret, docName)`,
with the same arguments and the same result.

## `PARTYKIT_TOKEN_TTL_SECONDS` is gone

Use `COLLAB_TOKEN_TTL_SECONDS`. It is the same number (300), for every engine.

Before:

```ts
import { PARTYKIT_TOKEN_TTL_SECONDS } from '@adonis-agora/collaboration'
```

After:

```ts
import { COLLAB_TOKEN_TTL_SECONDS } from '@adonis-agora/collaboration'
```

## Automerge: upgrade the server and the client together

The Automerge engine speaks one protocol: the client opens the socket with `doc` and `token`, gets
the whole document once, and from then on both sides exchange change chunks. The `sync=changes`
query parameter and the `CHANGES_ACK` export of `@adonis-agora/collaboration/drivers/automerge` are
gone. Deploy `@adonis-agora/collaboration` 1.0 and `@adonis-agora/collaboration-client` 1.0 in the
same release.

Before, if you opened the socket yourself:

```ts
import { CHANGES_ACK } from '@adonis-agora/collaboration/drivers/automerge'

const ws = new WebSocket(`${wsUrl}?doc=${docName}&token=${token}&sync=changes`)
ws.onmessage = (event) => {
  if (event.data === CHANGES_ACK) return
  // ...
}
```

After:

```ts
const ws = new WebSocket(`${wsUrl}?doc=${docName}&token=${token}`)
ws.onmessage = (event) => {
  // the first binary frame is the whole document, every later one a change chunk
}
```

With `useAutomergeDoc` there is nothing to change.

## A pre-issued token needs its `expiresAt`

A token handed to the client ahead of time (`initialTokens` / `initialToken`) is checked against
its `expiresAt` only. Pass the whole result of `issueCollaborationToken` through.

Before:

```ts title="app/researcher/controllers/writing_page_controller.ts"
const { token, wsUrl, engine } = await issueCollaborationToken({ ctx, docName })
return inertia.render('writing', { collabToken: { token, wsUrl, engine } })
```

After:

```ts title="app/researcher/controllers/writing_page_controller.ts"
const { token, wsUrl, engine, expiresAt } = await issueCollaborationToken({ ctx, docName })
return inertia.render('writing', { collabToken: { token, wsUrl, engine, expiresAt } })
```

A token without `expiresAt` is used as is, and the server refuses it if it has expired.

## `appKey` must be a `Secret`

Without a `tokenSecret`, the signing key comes from `appKey`, which must be exported as a
`Secret`. A plain string is no longer read, and token issuing fails with
`CollabTokenSecretMissingError`.

Before:

```ts title="config/app.ts"
export const appKey = env.get('APP_KEY')
```

After:

```ts title="config/app.ts"
import { Secret } from '@adonisjs/core/helpers'

export const appKey = new Secret(env.get('APP_KEY'))
```
